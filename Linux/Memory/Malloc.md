## kmalloc()
内核中最常用的内存分配函数
### 原型
```C
#include <linux/slab.h>
void *kmalloc(size_t size, gfp_t flags);
void kfree(const void *addr);
```
1. size：请求分配的内存字节数
2. flags：告诉内核如何去分配这块内存，尤其是在内存紧张时，最重要的标志分为两类，上下文 和 区域
3. GFP_KERNEL：最常用的标志。表示是在进程上下文中进行\
（1）如果内存不足，允许内核阻塞（睡眠）。内核会尝试换出旧的页，释放缓存\
（2）绝对不能在中断上下文中使用
4. GFP_ATOMIC：表示是在圆子上下文中进行，例如中断处理程序、软中断、或持有自旋锁的代码中\
（1）绝不允许内核阻塞（睡眠）。内核只会尝试从内存的“紧急预留区”中分配。如果预留区也没有内存，分配会立即失败并返回 NULL\
（2）保证分配函数能快速返回，不会导致系统在关键代码路径上休眠
5. GFP_DMA：区域修饰符。要求内核必须从 DMA 区域分配内存\
（1）仅用于某些老旧的 ISA 设备或特定的外设，它们只能对物理内存的低地址（例如前 16MB）执行 DMA 操作
### 地址连续性
虚拟地址和物理地址均连续
### 分配的内存
从内核的直接映射区分配内存，由于需要物理连续的内存，因此很难分配到非常大的内存块（通常最大为 128KB 或几 MB）
### 工作机制
1. 底层是基于 Slab 分配器 (如 SLUB, SLAB) 构建的。
2. Slab 分配器会维护许多特定大小对象（如 32 字节、64 字节、128 字节）的缓存池。
3. 当调用 kmalloc(50, ...)，Slab 分配器会快速地从 64 字节的缓存池中拿出一个空闲对象。
4. 如果缓存池空了，Slab 分配器会向更底层的伙伴系统申请新的、物理连续的内存页，然后将它们填充到缓存池中
### 用途
1. DMA：最主要的原因。硬件设备（如网卡）需要一块连续的物理内存缓冲区来直接读写数据
2. 需要高性能、频繁分配和释放的小型内核数据结构 
## vmalloc()
### 原型
```C
#include <linux/vmalloc.h>
//内核会自动将其向上舍入到页的整数倍
void *vmalloc(unsigned long size);
//在内部调用时默认会使用类似 GFP_KERNEL 的标志
void vfree(const void *addr);
```
### 地址连续性
虚拟地址连续，物理地址非连续
### 工作原理
1. 通过伙伴系统分配单个的物理页，然后在内核的虚拟地址空间中找到一块连续的地址范围
2. 手动建立页表映射，将这些分散的物理页拼装成一块连续的虚拟内存
3. 速度相对较慢。因为涉及分配多个页、查找连续的虚拟地址范围以及修改内核页表等开销
### 用途
1. 分配非常大的内存区域（例如几 MB 到几 GB），而这些内存又不需要用于 DMA
2. 加载内核模块的代码和数据
3. 用于某些大缓冲区，如 procfs 的 I/O 缓冲区
