## 物理结构
核心法则是：速度越快，成本越高，容量越小
### CPU 寄存器(Registers)
1. 位置： 在 CPU 芯片内部。
2. 速度： 最快（与 CPU 同一个时钟周期）。
3. 作用： 存储 CPU 正在处理的指令和数据（例如，当前指令、累加器、程序计数器）。
4. 容量： 极小（几十到几百个字节）
### CPU 缓存 (Cache)
1. 位置： 在 CPU 芯片上或非常靠近 CPU。
2. 速度： 极快（比寄存器慢，但比主存快几个数量级）。
3. 作用： 存储主存中近期最常访问的数据副本。CPU 会先在缓存中查找数据（缓存命中），找不到才去主存。
4. 分级：\
（1）L1 (一级缓存): 每个 CPU 核心独有，速度最快，容量最小（例如 64KB）。\
（2）L2 (二级缓存): 每个 CPU 核心独有或几个核心共享，速度和容量居中（例如 256 KB-1 MB）。\
（3）L3 (三级缓存): 所有 CPU 核心共享，速度最慢，容量最大（例如 8 MB-64 MB）
### 主存 (Main Memory / RAM)
1. 位置： 主板上的内存条（通常是 DRAM）。
2. 速度： 较快。
3. 作用： 存储着操作系统内核、所有正在运行的程序及其数据。
4. 特性： 易失性（断电后数据丢失）。
5. 容量： 较大（例如 8GB - 64GB）。
### 二级存储 (Secondary Storage)
1. 位置： 硬盘 (HDD) 或固态硬盘 (SSD)。
2. 速度： 慢（尤其是机械硬盘）。
3. 作用： 永久存储数据和程序。在现代操作系统中，它也用作虚拟内存的“交换空间”。
4. 特性： 非易失性（断电不丢失）。
5. 容量： 巨大（例如 512 GB - 10 TB+）
## Cache 映射
1. 连接 主存 和 CPU 缓存 之间的核心技术
2. 为了高效管理，主存和 Cache 都被划分为固定大小的“块”，也称为“缓存行”
### 解决问题
1. 主存非常大而 Cache 非常小。当 CPU 需要一块内存数据时（例如地址 0x1234ABCD），如何快速判断这块数据是否在 Cache 中
2. 如果不在，把它从主存取回后，应该放在 Cache 的哪个位置
### 内存地址分解
一个内存地址会被硬件（MMU 和 Cache 控制器）分解为三部分：
1. 偏移量: 块内的地址。如果块大小是 64 字节 (2^6)，则地址的低 6 位就是偏移量。
2. 索引: 决定这块数据应该放在 Cache 的哪一行。
3. 标签: 数据的“身份证”。用于区分映射到同一行的不同内存块
## 直接映射
### 工作原理
主存中的每一个块只能映射到 Cache 中的一个固定行
### 映射公式
Cache 行号 = (主存块号) % (Cache 总行数)
### 地址分解
[ Tag | Index | Offset ]，Index 字段直接决定了它去哪一行
### 查找过程
1. CPU 给出地址，硬件提取 Index
2. 硬件只检查 Index 指向的那一个 Cache 行
3. 比较该行的 Tag 是否与地址中的 Tag 相同
4. 如果 Tag 相同且 有效位 为 1，则 Cache 命中
5. 如果 Tag 不同或 有效位 为 0，则 Cache 未命中
### 优点
极其简单且快速： 硬件只需检查一个位置，电路简单，成本低
### 缺点
1. 高冲突未命中，致命弱点
2. 举例\
（1）假设一个 Cache 只有 8 行。如果程序需要交替访问主存中的第 0 块、第 8 块、第 16 块（Index 都是 0），它们会映射到 Cache 的同一行\
（2）CPU 访问第 0 块，第 0 块装入 Cache；接着访问第 8 块，第 8 块把第 0 块替换了出去\
（3）即使 Cache 其他 7 行都是空的，这三个块也会相互替换，导致 Cache 命中率极低
## 全相联映射
最灵活、最复杂、也最昂贵的一种方式
### 工作原理
主存中的任何块都可以被放置到 Cache 中的任何行。
### 地址分解
[ Tag | Offset ]，没有 Index 字段，因为没有固定的位置。
### 查找过程
1. CPU 给出地址，硬件提取 Tag
2. 硬件需要同时比较 Cache 中所有行的 Tag
3. 如果任何一个 Tag 匹配，则 Cache 命中
4. 如果所有 Tag 都不匹配，则 Cache 未命中
### 替换
如果 Cache 满了，需要一个替换策略（例如 LRU）来决定踢走哪一行
### 优点
冲突未命中最低，不会发生“直接映射”中两个块抢一个位置的情况
### 缺点
1. 极其昂贵且缓慢，假设一个有 1024 行的 Cache。为了实现“同时比较”，硬件需要 1024 个比较器。
2. 这种“内容寻址存储器”(CAM) 非常昂贵、复杂且耗电
## N 路组相联映射
上述两种方式的完美折中，也是现代 CPU 普遍采用的方式
### 工作原理
1. 将 Cache 分成 S 个组，每个组里有 N 行。
2. 主存中的一块首先直接映射到一个组，然后可以在这个组内的 N 行中全相联映射（即任意存放）。
### 映射公式
Cache 组号 (Index) = (主存块号) % (Cache 总组数 S)
### 地址分解
[ Tag | Index | Offset ]
### 查找过程
1. CPU 给出地址，硬件提取 Index
2. 硬件定位到 Index 指向的那一个组
3. 硬件同时比较该组内 N 个行的 Tag
4. 如果 N 个中有任何一个 Tag 匹配，则 Cache 命中
5. 如果全都不匹配，则 Cache 未命中
### 替换
如果一个组（例如一个 8-Way 的组）里的 8 行都满了，会使用 LRU 算法踢走该组内“最久未被使用”的那一行
