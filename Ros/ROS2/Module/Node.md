## 概念
最基本的构建块，一个可执行的进程，负责执行系统中的一个具体任务
### 计算单元
节点是 ROS2 中最小的可独立运行的单元
### 通信的壳
1. 节点本身只是一个空壳，真正作用是拥有和管理所有的通信组件
2. 一个节点可以包含：发布者/订阅者、服务器/客户端、Action 服务器/客户端、参数、定时器
### 命名与命名空间
1. 名称: 每个节点在系统中都必须有一个唯一的名称（例如 camera_driver）
2. 命名空间: 节点可以被分组到命名空间，例如，robot1/camera_driver 和 robot2/camera_driver，这允许在不冲突的情况下运行多个相同的节点
### 去中心化
1. ROS2 与 ROS1的最大区别，ROS2 中没有 roscore (ROS Master)
2. 节点是平等的，它们使用底层的 DDS（数据分发服务）自动发现网络上的其他节点及其提供的 Topic/Service 等
## 核心原理 
### 创建节点
1. 调用 std::make_shared<MyNode>() 时，这个节点是在已存在的上下文中被创建的
2. 调用 this->create_publisher(...) 时，实际上是在指示 DDS ：“创建一个 DDS DataWriter (数据写入器)，并向全网通告这个 Topic
3. 所有的管道 —— DDS 的 DataWriters 和 DataReaders 都已就位，但是还不会处理任何数据，处于休眠状态
### 执行器和等待集
1. rclcpp::spin(my_node) 是一个便捷函数，背后真正的工作如下
```
// rclcpp::spin(my_node) 实际上等同于...
rclcpp::executors::SingleThreadedExecutor executor; // 1. 创建一个执行器
executor.add_node(my_node);      // 2. 将节点"附加"到执行器
executor.spin();                  // 3. 开始无限循环
```
2. executor.spin() 不是在空转，而是做一个高效的事件循环，这个循环依赖于“等待集” 机制
### executor.spin()
executor.spin() 的单次循环详细步骤如下
1. 收集 : 执行器会询问所有附加给它的节点（这里只有 my_node）：“把你所有需要我监视的事件源都给我”。my_node 会交出：\
（1）它的订阅者（的 DataReader）\
（2）它的 timer_ 定时器\
（3）它可能有的 Service 服务器、Action 服务器等等\
（4）执行器把所有这些事件源打包成一个 等待集\
1. 等待：最关键的一步。执行器将这个等待集交给 DDS 或操作系统，并发出一个阻塞式的系统调用，直到这个集合中的任何一个事件源有变化才会被唤醒。这个线程会完全交出 CPU，CPU 占用率为 0%
2. 唤醒：假设：一个网络包到达了，DDS发现它是发给订阅者的，操作系统/DDS 会唤醒正在等待的执行器
3. 处理：执行器被唤醒后，它会检查等待集，找出是哪个事件触发了唤醒。从 DDS 的队列中取出这个新数据，并查找这个订阅者注册的回调函数，然后调用
4. 循环：当回调函数执行完毕并返回后，executor.spin() 回到第一步
### 回调队列与线程模型
1. SingleThreadedExecutor (单线程执行器，默认)\
（1）只有一个线程，在任何时刻，只有一个回调函数能被执行\
（2）在回调函数执行期间会完全阻塞，定时器不会被触发，对 Service 的请求不会被响应，所有其他 Topic 的消息都会被堆积在 DDS 的缓冲区里\
（3）所以在单线程模型中，回调函数必须是“非阻塞”的，必须尽快执行完毕并返回
1. MultiThreadedExecutor (多线程执行器)\
（1）可以手动创建：rclcpp::executors::MultiThreadedExecutor executor(4); (使用 4 个线程)\
（2）所有这 4 个线程同时在执行 spin() 循环，共享一个等待集和一个回调队列\
（3）当 4 条消息同时到达时，这 4 个线程可以并行地从队列中抓取任务，并同时执行 4 个回调函数\
（4）如果使用多线程执行器，节点类必须是线程安全的
