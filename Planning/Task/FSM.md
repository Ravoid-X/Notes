## 概述
1. 有限状态机（Finite State Machine, FSM）是机器人任务规划中最基础也最经典的控制架构
2. 因逻辑清晰、实现简单而被广泛应用于从简单的巡逻机器人到复杂的工业流程控制中
## 原理
在任务规划的语境下，FSM 将机器人的行为离散化为有限个状态，并定义了状态之间跳转的规则
### 数学模型
一个有限状态机 $M$ 可以表示为一个五元组
$$M = (Q, \Sigma, \delta, q_0, F)$$
1. $Q$：状态集合。有限个状态的集合 $\{q_1, q_2, ..., q_n\}$（例如：待机、移动、抓取）
2. $\Sigma$：输入字母表。触发转换的外部或内部事件集合（例如：发现目标、电池低、到达目的地）
3. $\delta$：转换函数。映射规则 $\delta: Q \times \Sigma \rightarrow Q$。即“当前状态 + 特定事件 = 下一个状态”
4. $q_0$：初始状态
5. $F$：终止状态集合
### 核心机制
依赖于“感知-决策-执行”的循环
1. 状态驻留：当机器人在某个状态时，持续执行该状态对应的动作（例如在 Moving 状态下发布速度指令）。
2. 事件触发：系统不断监测外部环境（传感器数据）或内部状态（定时器、标志位）。
3. 状态流转：一旦满足转换条件，系统立即切换到新状态，通常伴随 OnExit（退出旧状态）和 OnEnter（进入新状态）的一次性操作
## 算法步骤
在工程实现中，FSM 通常嵌入在一个高频控制循环中
### 初始化
1. 定义所有可能的状态（枚举类型）
2. 设置初始状态 $q_0$
3. 初始化传感器订阅和执行器发布接口
### 循环检测
在每一个控制周期内
1. 感知更新\
（1）读取传感器数据（雷达、电池电压、里程计）\
（2）更新世界模型
2. 检查转换条件\
（1）根据当前状态，检查该状态下所有可能的出边\
（2）如果满足条件（如 battery < 20%），则执行状态切换逻辑
3. 执行当前状态行为\
（1）调用 CurrentState.Run()\
（2）例如：如果当前是“导航状态”，则向 Navigation Stack 发送 Goal；如果是“充电状态”，则检查充电触点
