## 概述
本质上是程序试图访问一块没有权限访问的内存区域。操作系统为了保护内存安全，会发送 SIGSEGV 信号，导致程序异常终止。
## 访问空指针
试图读取或写入一个空指针所指向的内存时，程序会立即崩溃。
## 访问未初始化的指针
未初始化的指针持有随机地址，访问它几乎总会导致未定义行为，最常见的就是段错误。
## 访问悬垂指针
### 访问 delete 后的内存
1. delete 指针后，内存被操作系统回收，但指针变量本身仍然持有旧地址。
2. delete 指针后，立即将其设为 nullptr。后续访问会触发空指针异常，而不是更难排查的悬垂指针问题。
### 访问已销毁的栈内存
1. 通常发生在你返回一个指向函数局部变量的指针或引用时。
2. 函数返回后，其栈帧被销毁，局部变量随之消失，返回的指针就成了悬垂指针。
## 数组/缓冲区越界
### 栈数组越界
轻微的越界（如 arr[10]）不一定会立即导致段错误，但它会破坏栈上的其他数据（如其他局部变量，甚至函数返回地址），这可能导致程序在稍后崩溃
```
int main() {
    int arr[10]; 
    arr[10] = 5; // <-- 越界
    // 严重越界，几乎必然导致段错误
    arr[10000] = 1; // <-- 段错误
}
```
### 堆数组越界
```
int main() {
    int* arr = new int[10]; 
    arr[10] = 5; // <-- 越界，行为未定义
    delete[] arr;
    return 0;
}
```
## 试图修改只读内存
1. 字符串字面量（例如 "hello"）通常存储在程序的只读数据段中
```
int main() {
    // s 指向一块只读内存
    char* s = "hello world"; 
    s[0] = 'H'; // <-- 段错误
    return 0;
}
```
2. 如果需要修改字符串，使用栈上的 char 数组或 std::string
```
// 修复方法 1: 栈数组 (拷贝)
char s[] = "hello world";
s[0] = 'H';
// 修复方法 2: std::string
std::string s = "hello world";
s[0] = 'H';
```
## 栈溢出
1. 虽然 栈溢出 是一个专门的术语，但它最终的表现形式通常就是段错误
2. 最常见的原因是无限递归或深度过大的递归
